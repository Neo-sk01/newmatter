# Requirements Document

## Introduction

This specification focuses on implementing AI-powered features using the Vercel AI SDK across the SalesMatter platform. THE System SHALL leverage the Vercel AI SDK to provide intelligent CSV column mapping, lead data enrichment, and personalized email generation capabilities.

## Glossary

- **System**: The SalesMatter web application
- **User**: A sales professional using the platform
- **Vercel_AI_SDK**: The AI SDK library providing streamText and generateObject functions
- **AI_Mapper_Endpoint**: The API route at `/api/map-csv` that uses AI to map CSV columns
- **Research_Endpoint**: The API route at `/api/enrich-lead` that performs AI-powered lead research
- **Email_Generator_Endpoint**: The existing API route at `/api/generate-email` that creates personalized emails
- **Lead_Schema**: The canonical data structure (firstName, lastName, company, email, title, website, linkedin)
- **Structured_Output**: JSON responses generated by AI using the generateObject function with Zod schemas
- **Streaming_Response**: Real-time text generation using the streamText function

## Requirements

### Requirement 1: AI-Powered CSV Column Mapping

**User Story:** As a User, I want the system to intelligently map my CSV columns to the correct lead fields using AI, so that I can import data from any format without manual configuration.

#### Acceptance Criteria

1. WHEN the User uploads a CSV file, THE System SHALL send column headers and up to 5 sample rows to the AI_Mapper_Endpoint
2. WHEN the AI_Mapper_Endpoint receives the request, THE System SHALL use the Vercel_AI_SDK generateObject function with a Zod schema to produce structured mapping output
3. THE System SHALL use the gpt-4o-mini model for column mapping operations
4. THE System SHALL return a JSON mapping object where keys are original column names and values are Lead_Schema field names
5. WHEN a column contains full names, THE System SHALL map it to both firstName and lastName with a split indicator

### Requirement 2: Intelligent Name Splitting

**User Story:** As a User, I want the system to automatically split full name columns into first and last names, so that my lead data is properly structured for personalization.

#### Acceptance Criteria

1. WHEN the AI_Mapper_Endpoint detects a full name column, THE System SHALL include instructions in the AI prompt to identify name splitting requirements
2. THE System SHALL return a mapping that indicates which column requires name splitting
3. WHEN processing CSV rows, THE System SHALL split full names on the first space character
4. THE System SHALL handle edge cases where names have no space by using the entire value as firstName
5. THE System SHALL trim whitespace from firstName and lastName values after splitting

### Requirement 3: AI-Powered Lead Enrichment

**User Story:** As a User, I want to enrich my leads with AI-generated research summaries, so that I can personalize my outreach with relevant insights.

#### Acceptance Criteria

1. WHEN the User requests lead enrichment, THE System SHALL send lead data to the Research_Endpoint
2. WHEN the Research_Endpoint receives the request, THE System SHALL use the Vercel_AI_SDK streamText function to generate research summaries
3. THE System SHALL use the gpt-4o model for lead enrichment operations to ensure high-quality research
4. THE System SHALL limit research summaries to 100 words maximum using the maxOutputTokens parameter
5. THE System SHALL stream the research summary to the client in real-time for immediate User feedback

### Requirement 4: Contextual Research Prompts

**User Story:** As a User, I want the AI to generate relevant research based on available lead information, so that the enrichment is tailored to each prospect.

#### Acceptance Criteria

1. WHEN generating research prompts, THE System SHALL include all available lead fields (name, company, title, website, linkedin)
2. WHERE a lead has a LinkedIn URL, THE System SHALL instruct the AI to focus on professional background and recent activity
3. WHERE a lead has a company website, THE System SHALL instruct the AI to research company news and initiatives
4. THE System SHALL structure research prompts to request specific insights about pain points, recent achievements, and relevant talking points
5. THE System SHALL include instructions to avoid generic statements and focus on actionable intelligence

### Requirement 5: Enhanced Email Generation

**User Story:** As a User, I want generated emails to incorporate enrichment data, so that my outreach is personalized and relevant to each prospect.

#### Acceptance Criteria

1. WHEN the User generates an email for an enriched lead, THE System SHALL include the research summary in the generation prompt
2. THE System SHALL use the existing Email_Generator_Endpoint with the Vercel_AI_SDK streamText function
3. THE System SHALL instruct the AI to reference at least one specific insight from the research summary in the email body
4. THE System SHALL maintain the existing 700 token limit for email generation
5. THE System SHALL stream the generated email content to the client for real-time preview

### Requirement 6: Model Configuration and Flexibility

**User Story:** As a User, I want to configure which AI models are used for different tasks, so that I can optimize for cost, speed, or quality.

#### Acceptance Criteria

1. THE System SHALL read model configuration from environment variables AI_EMAIL_MODEL and AI_RESEARCH_MODEL
2. THE System SHALL support the format "provider:model" for model identifiers (e.g., "openai:gpt-4o-mini" or "anthropic:claude-3-5-sonnet-20241022")
3. THE System SHALL default to "openai:gpt-4o-mini" for email generation if AI_EMAIL_MODEL is not set
4. THE System SHALL default to "openai:gpt-4o" for research if AI_RESEARCH_MODEL is not set
5. THE System SHALL parse model identifiers and use the appropriate SDK provider (openai or anthropic)

### Requirement 7: Structured Output Validation

**User Story:** As a User, I want the system to validate AI responses, so that I receive consistent and reliable data structures.

#### Acceptance Criteria

1. WHEN using generateObject for column mapping, THE System SHALL define a Zod schema that enforces the mapping structure
2. THE System SHALL validate that all returned field names are valid Lead_Schema fields
3. IF the AI returns an invalid field name, THEN THE System SHALL reject the mapping and return an error
4. THE System SHALL ensure the mapping object contains at least one valid field mapping
5. THE System SHALL handle Zod validation errors gracefully and provide clear error messages to the User

### Requirement 8: Error Handling and Fallbacks

**User Story:** As a User, I want the system to handle AI failures gracefully, so that I can continue working even when AI services are unavailable.

#### Acceptance Criteria

1. WHEN the AI_Mapper_Endpoint fails, THE System SHALL fall back to heuristic column mapping based on common patterns
2. WHEN the Research_Endpoint fails, THE System SHALL display an error message and allow the User to retry
3. WHEN the Email_Generator_Endpoint fails, THE System SHALL display an error message and preserve the User's template input
4. THE System SHALL log AI errors to the server console for debugging purposes
5. THE System SHALL return HTTP 500 status codes with descriptive error messages when AI operations fail

### Requirement 9: API Key Management

**User Story:** As a User, I want the system to securely manage API keys, so that my credentials are protected.

#### Acceptance Criteria

1. THE System SHALL read OPENAI_API_KEY from environment variables for OpenAI model access
2. THE System SHALL read ANTHROPIC_API_KEY from environment variables for Anthropic model access
3. THE System SHALL never expose API keys in client-side code or API responses
4. IF a required API key is missing, THEN THE System SHALL return an error message indicating which key is needed
5. THE System SHALL validate API keys by attempting a test request during application startup

### Requirement 10: Performance Optimization

**User Story:** As a User, I want AI operations to complete quickly, so that I can maintain productivity during lead processing.

#### Acceptance Criteria

1. WHEN mapping CSV columns, THE System SHALL limit sample data to 5 rows to minimize token usage
2. WHEN generating research summaries, THE System SHALL set temperature to 0.7 for balanced creativity and consistency
3. WHEN generating emails, THE System SHALL set temperature to 0.7 for personalized yet professional content
4. THE System SHALL use streaming responses for all text generation to provide immediate feedback
5. THE System SHALL implement request timeouts of 30 seconds for all AI operations

### Requirement 11: Token Usage Monitoring

**User Story:** As a User, I want to understand token usage for AI operations, so that I can manage costs effectively.

#### Acceptance Criteria

1. THE System SHALL log token usage to the server console for each AI operation
2. THE System SHALL include prompt tokens, completion tokens, and total tokens in logs
3. THE System SHALL calculate estimated costs based on model pricing and log the amounts
4. WHERE available, THE System SHALL use the usage metadata from AI SDK responses
5. THE System SHALL aggregate token usage statistics for display in a future admin dashboard

### Requirement 12: Prompt Engineering Best Practices

**User Story:** As a User, I want AI-generated content to be high quality, so that I can use it with minimal editing.

#### Acceptance Criteria

1. THE System SHALL use clear, specific system prompts that define the AI's role and constraints
2. THE System SHALL structure prompts with explicit instructions, examples, and output format requirements
3. THE System SHALL include negative instructions to prevent unwanted behaviors (e.g., "do not use generic greetings")
4. THE System SHALL provide context about the User's goals and the lead's background in generation prompts
5. THE System SHALL iterate on prompts based on User feedback to improve output quality over time
